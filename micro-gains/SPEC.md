# Micro Gains spec

Micro Gains pings you at an interval you choose during your waking hours with one
tiny bodyweight set (ten push-ups, fifteen air squats, a one-minute plank). You
do it, tap Done, and get on with your day. For people who want to be fit but
can't get to a gym.

This file is the contract between the iOS app (`ios/`) and the Worker
(`server/`). Change both sides when you change it.

## Architecture

- iOS app, UIKit only, iOS 17+, no storyboards, xcodegen `project.yml`.
- Cloudflare Worker + D1 in `server/`. TypeScript, wrangler, vitest.
  Production: https://micro-gains.onemany.workers.dev (One&Many Cloudflare
  account, D1 `micro-gains-db`).
- Notifications are local (`UNUserNotificationCenter`), scheduled on-device. No
  APNs. The app fills the pending queue as far into the future as the budget
  allows (60 requests; iOS caps pending local notifications at 64 and we keep
  4 spare for snoozes) and tops it up on launch, on foreground, after settings
  changes, and from a `BGAppRefreshTask`. Background refresh is best-effort, so
  never depend on it: the horizon is what keeps reminders flowing when the app
  isn't opened for days.
- Auth is a device UUID. The app generates it once, stores it in Keychain, and
  sends it as `X-Device-Id` on every `/api/*` call. The server upserts the
  device on first sight. No passwords, no accounts. Same posture as Read the
  Bible's reader cookie. Anyone holding the UUID is that device.
- The app must work fully offline. Server sync is best-effort: settings are
  pushed after edits, completed sets are queued locally and flushed when
  online. The catalog is bundled (`catalog.json`) and refreshed from the
  server when available.

## Domain

### Exercise (catalog)

```
id        text, snake_case, stable ("push_up")
name      text ("Push-ups")
pattern   push | squat | hinge | core | cardio | mobility
unit      reps | seconds
easy      int  target at easy
medium    int  target at medium
hard      int  target at hard
cue       text, <= 12 words of form cue
office_ok bool
needs_floor bool
intense   bool  high-intensity cardio (see scheduling rule 4c and the body
                templates in rule 5). false for everything else
```

Canonical catalog lives in `/micro-gains/catalog.json` (from RESEARCH.md). The
server seeds it into D1 and serves it; the app bundles the same file.

### Settings (per device)

```
interval_minutes     int   one of 60, 90, 120, 180, 240. default 120 (RESEARCH.md:
                           nothing under 60 min has evidence or notification tolerance)
difficulty           text  easy | medium | hard. default medium
active_start_minute  int   minutes after local midnight, default 540 (09:00)
active_end_minute    int   default 1140 (19:00). must be > start + interval
active_days          int   7-bit mask, bit0 = Monday ... bit6 = Sunday. 1..127 (never 0;
                           use enabled/paused_until to pause). default 127
office_mode          bool  default false. when true, only office_ok exercises
floor_ok             bool  default true. when false, exclude needs_floor
enabled              bool  default true. false = paused, no notifications
paused_until         text|null ISO8601. "Pause until tomorrow" sets this to the
                           next active-window start; scheduler skips slots before it
exercise_levels      object {exercise_id: "easy"|"medium"|"hard"} per-exercise
                           override. Written when the user answers "Too hard" on a
                           skip (drops that exercise one level). Empty by default
timezone             text  IANA, from the device. Stored on `devices`, returned
                           inside settings for convenience
updated_at           text  server-set, returned on every read
```

Sync is single-device and client-wins. The last `PUT` is the truth; the app
pulls settings from `/api/me` only when it has none locally (fresh install).

### Set log

```
id            text uuid, generated by the client
exercise_id   text
target        int  reps or seconds prescribed
unit          reps | seconds (snapshot so history survives catalog edits)
status        done | skipped
skip_reason   null | bad_time | too_hard | not_here
scheduled_at  text ISO8601 with offset, the jittered delivery time of the
              notification (null if user started one manually)
logged_at     text ISO8601 with offset, when Done/Skip was tapped
local_date    text YYYY-MM-DD in the device's zone at logged_at
source        notification | app
```

### Scheduling rules (client)

Implemented in a pure, unit-tested `Scheduler` type with no UIKit imports.
It takes settings, the catalog, the current date, the device id, and recent
history, and returns a list of `Slot`s.

1. Slot generation uses `Calendar` with the device's time zone so DST gaps and
   repeats are handled (a slot at a non-existent local time is dropped; a
   repeated hour gets one slot). Slots are every `interval_minutes` from
   `active_start_minute` up to and not including `active_end_minute`, on
   `active_days`, skipping anything before `paused_until`. Start with the first
   slot strictly after "now". Produce slots day after day until 60 slots are
   collected or 14 days are covered.
2. Jitter: each slot shifts by a deterministic pseudo-random offset in
   [-5, +5] minutes derived from `hash(device_id, unjittered slot time)`, clamped
   so it stays inside the active window and never crosses the adjacent slot.
   Re-running the scheduler always produces the same jitter for the same slot.
3. Notification request identifier = `"slot-" + unjittered slot time in
   ISO8601 UTC`. `set_id` = UUID v5 of that identifier (deterministic). Reschedule
   is a diff: fetch pending requests, remove identifiers no longer wanted, add
   missing ones. Never remove-all-then-add unless `enabled` is false.
4. Exercise selection is constrained random, deterministic per slot (seeded the
   same way as jitter), evaluated in order with fallbacks so it is always
   satisfiable:
   a. Eligible = catalog filtered by `office_mode` (only `office_ok`) and
      `floor_ok` (drop `needs_floor` when false). If empty, ignore the filters.
   b. Exclude the previous slot's pattern. Exclude any pattern already used
      twice that local day, and any pattern used within the last 3 hours of
      generated slots. If that empties the set, relax in reverse order.
   c. The first slot of a local day may not be a `cardio` item flagged
      high-intensity (`jumping_jacks`, `high_knees`, `stair_climb`,
      `mountain_climbers` and similar; mark these with `intense: true` in the
      catalog). No warm-up exists in this product. The last slot of a day
      prefers `mobility` (2x weight).
   d. Among remaining patterns prefer the one used least across the previous 6
      generated slots; ties broken by seed. Within that pattern exclude the
      previous two exercises and anything used in the last 24 h of slots if
      more than one candidate remains.
   e. Target = catalog value at `exercise_levels[id] ?? difficulty`.
   History for (b) and (c) is the sequence of generated slots (including ones
   already pending), not completions, so reopening the app never reshuffles
   what's already queued.
5. Each notification: title is the prescription ("15 air squats"; for seconds
   "Plank, 45 seconds"), body is the cue. Because identical prompts decay
   (HeartSteps, RESEARCH.md), rotate the body among a few templates chosen by
   seed: plain cue; cue plus "Set 3 of 6 today"; cue plus the streak ("Day 4");
   and for `intense` cardio the effort line "Hard enough that talking is tough". Category `MICRO_SET`, actions `Done`, `Skip`, `Snooze 10 min`.
   Done/Skip log a set without opening the app. Snooze removes the original
   request and adds one with identifier `<id>-snooze` firing in 10 minutes,
   same `set_id`; only one snooze per slot. `userInfo` carries `exercise_id`,
   `target`, `unit`, `scheduled_at`, `set_id`.
6. Slot lifecycle, kept in the local store keyed by `set_id`:
   `scheduled -> delivered -> (done | skipped | expired)`; `snoozed` is a
   flag on a delivered slot. The first terminal write wins (Done from the
   notification action vs. Done on the Set screen can't both log). `expired`
   is assigned when the next slot's time passes with no answer; it is not a
   skip and is not shown as a failure.
7. If `enabled` is false, remove all pending requests. If `paused_until` is in
   the future, keep the pipeline but skip slots before it.
8. Settings shows a live line under the controls: "About 9 sets a day" computed
   from interval and active hours. Onboarding shows the same line before asking
   for notification permission.

## API

Base path `/api`. JSON in and out. Every route except `/health` requires
`X-Device-Id` (UUID v4, lowercased). Missing or malformed returns 401
`{"error":"device_required"}`. Unknown routes 404 `{"error":"not_found"}`.
Errors are `{"error": "<snake_case_code>", "message"?: string}`.

```
GET  /health
     200 {"ok":true,"db":true}

GET  /api/catalog
     200 {"exercises":[Exercise...],"version":"<sha256 of content>"}
     Sends ETag = version; honors If-None-Match with 304.

GET  /api/me
     200 {"device_id":..., "settings":Settings, "stats":Stats, "created_at":...}
     Creates the device with default settings if new.

PUT  /api/settings
     body Settings (full object, minus updated_at). Validates every field.
     Writes settings and devices.timezone in one D1 batch.
     200 {"settings":Settings}
     400 {"error":"invalid_settings","message":...}
     400 {"error":"invalid_json"} for unparseable or non-JSON bodies. Bodies
     over 64 KB get 413 (256 KB for POST /api/sets).

POST /api/sets
     body {"sets":[SetLog...]}  (batch, idempotent on (device_id, id); 1..200 items)
     Validates exercise_id exists, target 1..1000, status/source/skip_reason
     enums, timestamps parse and are not more than 1 day in the future,
     local_date matches logged_at in the device's time zone (server recomputes
     and stores its own value when they disagree).
     200 {"accepted":n,"duplicates":m,"rejected":[{"id":...,"error":...}],"stats":Stats}

GET  /api/history?days=30   (1..365, default 30)
     200 {"days":[{"date":"YYYY-MM-DD","done":n,"skipped":n,"reps":n,"seconds":n}...],
          "stats":Stats}
     One entry per calendar day in range, zeros filled.

DELETE /api/me
     204. Deletes device, settings, sets. (Settings screen "Erase my data".)
```

### Stats

```
today_done        int   sets done on the device's local today
today_skipped     int
streak_days       int   consecutive active days (per active_days mask, ending today or the
                        most recent active day) with >= 1 done. Rest days neither break
                        nor extend the streak
best_streak_days  int
total_done        int
total_reps        int   sum of target where unit = reps and status = done
total_seconds     int   sum of target where unit = seconds and status = done
```

Server computes "today" using the device's stored `timezone`. `/health`
returns 503 `{"ok":false,"db":false}` when the D1 probe fails.

## D1 schema (`server/migrations/0001_initial.sql`)

```
devices   (id TEXT PK, created_at TEXT, last_seen_at TEXT, timezone TEXT)
settings  (device_id TEXT PK FK ON DELETE CASCADE, interval_minutes, difficulty,
           active_start_minute, active_end_minute, active_days, office_mode,
           floor_ok, enabled, paused_until, exercise_levels TEXT (JSON), updated_at)
exercises (id TEXT PK, name, pattern, unit, easy, medium, hard, cue, office_ok,
           needs_floor, sort_order)
sets      (device_id TEXT FK ON DELETE CASCADE, id TEXT, exercise_id, target, unit,
           status, skip_reason, scheduled_at, logged_at, local_date, source,
           PRIMARY KEY (device_id, id))
index sets(device_id, local_date)
CHECK constraints on every enum and range.
```

## iOS app

xcodegen. Targets: `MicroGains` (app), `MicroGainsTests` (unit tests for

### Screens

Keep it to three main screens plus onboarding. No tab bar.

0. **Onboarding** (first launch only, a paged flow the user can swipe or tap
   Next through, 4 pages, each one idea, big type, one illustration-free
   line of copy and at most one control):
   1. "Tiny sets. All day." with a two-line pitch: "Micro Gains pings you a
      few times a day with one quick set. Ten push-ups. A minute plank. That's
      it."
   2. "How often?" interval picker (default 2 h) and active hours
      (default from RESEARCH.md), with the live "About N sets a day" line.
   3. "How hard?" Easy / Medium / Hard with the example line under each.
      Plus the Office mode switch ("I'm mostly at a desk").
   4. "Let us ping you." One sentence, one button **Turn on notifications**
      that triggers the system prompt. If denied, show a quiet line with a
      link to Settings and still let them in.
   Finishing writes settings, schedules the first batch, and shows Home with
   "First set at 2:15 PM". The flow must be completable in under 30 seconds.
   Onboarding is re-openable from Settings ("Show intro again").

1. **Home** (root). Black background.
   - Big next-ping line: "Next set at 2:15 PM" (or "Paused", or "Done for
     today" after the window closes), with the exercise hidden (the surprise
     is part of it).
   - Today: "4 done, 5 to go" and a row of small dots, one per slot in
     today's window: filled green = done, hollow = still coming, dim = skipped
     or expired. No red, no X marks. Missed sets are not debt.
   - Streak line: "3-day streak".
   - One primary button: **Do one now** (picks a set with the same rules and
     opens the Set screen).
   - Nav bar: gear (Settings) on the right, "History" text button on the left.
2. **Set** (modal, also what a notification tap opens). Exercise name huge,
   target huge ("15" with "air squats" under it), the cue in one line. For
   `seconds` exercises a big countdown ring with Start. Two buttons: **Done**
   (green, full width) and **Skip** (quiet). Done shows a 0.6 s check and
   dismisses. Skip shows a tiny three-option sheet: "Bad time", "Too hard",
   "Can't here". "Too hard" drops that exercise one level (`exercise_levels`)
   and says so in one line ("Push-ups are now easy: 5 reps").
3. **Settings** (pushed). Grouped list:
   - Remind me every: 1 h / 1.5 h / 2 h / 3 h / 4 h
   - Difficulty: Easy / Medium / Hard, with a one-line example under it
     ("Medium: 10 push-ups, 15 squats, 45 s plank")
   - Active hours: start and end time pickers
   - Days: seven toggles Mon..Sun
   - Office mode switch ("Only sets you can do at a desk")
   - Floor exercises switch
   - Pause until tomorrow (button) and Pause (switch)
   - Notifications permission row (opens system settings if denied)
   - Erase my data (destructive, confirm)
4. **History** (pushed). Last 30 days as a simple bar strip plus totals.

### Look

- Background `#000000`. Surface `#0E1411`. Primary green `#1F7A3A`, bright
  accent `#34C759`-ish but slightly desaturated `#3DDC6A`. Text white, secondary
  `#9BA8A0`. Red only on Erase.
- SF Pro via system fonts. Large rounded numerals for targets
  (`.rounded` design, weight bold, 96pt on the Set screen).
- Corner radius 14. Buttons 56pt tall. Minimum tap target 44pt.
- Copy is short and plain. Button labels are verbs. No exclamation points.
- Respect Dynamic Type and `reduceMotion`. VoiceOver labels on every control.
- App icon: a simple green upward-step mark on black. 1024 PNG generated by
  script (no external tools needed; a Swift or Python script is fine).

### Local storage

- `UserDefaults` (suite) for settings and the catalog cache.
- A JSON file in Application Support for the slot/set log, owned by an
  `actor SetStore`, written with `.atomic`, holding slot state and a `synced`
  flag per set. The app and the notification-action path share this one
  actor, so writes are serialized. Keep it dumb; no Core Data.
- Keychain for the device id.

### Notification handling

- Register the `MICRO_SET` category at launch, before anything else.
- Request authorization on first Home appearance after a short explainer
  card ("Micro Gains only works if it can ping you. About 9 sets a day with
  your current settings."), not on launch.
- Always call the response completion handler; do store writes inside a
  background task so iOS doesn't kill the action handler mid-write.
- `UNUserNotificationCenterDelegate` in AppDelegate: handle `Done`/`Skip`/
  `Snooze` actions in the background; default tap opens Set screen.
- Show banners in foreground too.

## Done means

- `cd server && npm test && npm run check` green; `wrangler dev` serves every
  route per this spec against local D1.
- `cd ios && xcodegen generate && xcodebuild ... -destination 'iPhone 17' test`
  green, and the app runs in the simulator, schedules notifications, and a
  fired notification's Done action logs a set and syncs to the local Worker.
